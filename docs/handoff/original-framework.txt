General Fear Exposure App
Meta global ai developer hackathon brainstorm


Concept
A stereographic VR app meant to help people train for uncomfortable and/or high-stakes
situations through practice and exposure. A user describes their fear and current ability to
handle it, and our system constructs a timed simulation. Examples might be public speaking, job
interviews, getting lost on a trail, or getting trapped in tight spaces. The program is meant to
push the user towards level-headed critical thinking and problem solving in uncomfortable
and/or high-stakes situations. It’s worth stating here explicitly that this is not meant to be a
mental health advisement product, since those are discouraged in the hackathon.

Core Engagement Loop
Primarily operated through audible commands and feedback. There is a dedicated preloader
screen for all page transitions, that displays different tips based on what the user’s transition
endpoint is. Putting the phone into portrait mode also pauses the app until it is returned to
landscape mode. Transitions between pages should play a whooshing wind noise.
    -​ User opens app
           -​ There is the simple preloader screen with tips
        -​  When the app loads, the first thing the user sees is a 3D preset forest parallax
            scenery (with depth so that it fades off into the atmosphere)
        -​ What do they hear?
                -​ Royalty free piano music plays in the background ALONGSIDE
                     atmospheric forest/wind noise
        -​ What are they able to do?
                -​ Contrasting-color (to the background) text on the screen says “When
                     you’re ready to start, say START!”
-​   User sets up headset
        -​ Check that the headset is set up
                -​ “It looks like you’re in portrait mode! Make sure you’ve got your headset
                     on before you start a simulation!”
        -​ Get voice-confirmation from user to start
-​   User describes fear
        -​ If there is information in the app’s SESSIONS spreadsheet that is relevant to the
            described fear, ask whether the user would like that to be taken into account
                -​ “I see we’ve explored this situation before! Would you like to consider
                     past sessions for this simulation?”
                -​ If this is a chained session from the “would you like to go again” part at
                     the end of sessions, then don’t ask.
        -​ Scene-maker/coordinator AI is sent a prompt. The prompt describes the context
            of the app, the user’s input, the goal of the model, examples of ideal outputs, and
            the entire suite of tools/options the model has available.
                -​ We will use an OpenAPI schema for this (it’s what I usually do and it
                     works well). I usually outline the stuff and then ask GPT or Gemini to
                     make a schema.
        -​ Other models construct their dedicated part (setting, sounds) of the scene
            according to the instructions of the initial coordinating model, so that everything is
            coherent.
                -​ Once the scene-coordinating model has made decisions, decisions are
                     made: unless further user input is entered.
                -​ We will also want to have schemas to give these models as well
-​   User waits for scene setup
        -​ The narrator says: “I’ll get the scene ready. If there’s anything additional you’d
            like to say, just say ‘hey builder!’ and let me know!”
        -​ Preloader screen should always display this tip first here:
                -​ “To stop at any time, just say STOP!”
        -​ Ideally, generation should take no more than 2 minutes. It should take around a
            minute on average.
-​   User experiences scene
        -​ The screen is black, and the narrator describes the scene in 8 seconds before
            the black fades away and the scene (blurry at first) fades into view.
                -​ In those 8 seconds, the narrator also reminds the user of the STOP
                     command
           -​  The user halts the simulation at any time by saying “STOP!”
                   -​ This causes everything to pause. A black-tinted overlay with a white text
                        display shows “Quit simulation?”. The user says “yes” to skip the rest of
                        the simulation or “no” to resume (basically undoing everything that STOP
                        did).
           -​ Timer counts down
                   -​ A timer counts down from a set amount of time chosen by the
                        scene-coordinating model
   -​   User gives feedback
           -​ Self-report experience
           -​ Optional vocal-reflection that is transcribed and saved to a “Reflections” folder in
               the app folder
                   -​ Filename is “[DATE]
                   -​ [HH::MM] - [SIMULATION TOPIC (<=30 characters)]”
   -​   User optionally receives feedback/analysis
           -​ “Would you like to hear feedback on your experience?”
           -​ Here’s what you did well
                   -​ 3 things maximum (positive only)
           -​ I also noticed…
                   -​ 3 things maximum (each can be either positive or negative. Doesn’t
                        matter)
                   -​ If it’s relevant, include at least one smaller thing that the user can fix
                        quickly, so that initial difficulty does not feel insurmountable
           -​ Obviously, this would need to be the work of an agent, and so we’d need an
               OpenAPI schema here as well.
   -​   Save session information to the app’s SESSIONS spreadsheet
           -​ The spreadsheet should have a conservative column-count and be designed to
               prioritize conveying information (especially the topics and the quantitative values)
               for mass review and cross-session pattern recognition.
   -​   User optionally goes again at an adapted level or returns to initial action screen
           -​ “Based on your last performance, would you like to go again?”
           -​ The one that says “when you’re ready to start, say START!”
