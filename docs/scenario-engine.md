# AI-authored scenario execution

Braive takes a freeform situation and current ability. Spark authors an ordered experience: objective, stages and meaningful actions. Wonder realizes that same plan as geometry, actors, paths, environmental changes and local voice commands. The phone executes those declarative instructions. It does not select a scene based on a topic keyword.

Skydiving, swimming and racing are examples in authoring guidance and tests. There are no production topic branches, embedded example scenes, or silent prerecorded/preset substitutes. The deterministic fixture under `tests/fixtures` exercises the generic runtime and is not an app resource. A generated scene can be bundled only through the explicit, ignored `Review` directory and `--include-review` diagnostic build option; normal generation excludes it.

## Shared capabilities

| AI-authored data | Native behavior |
| --- | --- |
| Ordered scenario steps | Current prompt/actions, timed or movement-completion progression, terminal goal |
| Literal action phrases | Apple on-device recognition followed by local execution |
| World or relative motion paths | Continuous participant/actor translation from the current position; relative paths use captured heading |
| Moving actor plus walk/run/swim behavior | Translation and app-owned joint motion on the registered neutral rig |
| Viewer-carried assembly roots | Equipment travels with translation while head rotation remains independent |
| Material/environment operations | Visibility, recoloring, opacity, thin surfaces, fog and lighting changes |
| Optional explicit conversation | ASK name or TALK TO name; no default first-character response |

The same monotonic active clock drives countdown, viewer/actor motion and character animation. STOP and interruptions freeze it; resumption continues from the preserved position/time. An in-flight absolute route is not restarted by repeating its command. Relative actions can make additional progress when repeated.

Only actions belonging to the current stage execute. A command for a later stage cannot skip the sequence. Repeated command IDs in different stages are valid; duplicates inside one stage are rejected. Scenario changes cancel stale optional character replies. Action experiences disable dialogue entirely. Conversation experiences may permit it, but the primary task still has an explicit structure.

## Coherence and limits

Coordinator cast, scene-node IDs, colors, approved props, stage IDs and stage action IDs must match. Licensed GLBs remain intact. The coordinator can select a registered clothed adult asset; skin/hair are preserved while clothing receives the approved tint. A supported sit pose persists through dialogue. Missing props can use AI-authored procedural assemblies bound to an approved prop name. This does not permit invented asset IDs or replacement character meshes.

The backend validates graph references, stage order, path timing, meaningful actions, actual requested movement and resource bounds. Native preflight builds the real geometry offscreen and checks task visibility and visible surface depth in both eyes. Its depth pass measures each surface fragment rather than treating a large plane as entirely located at its center. A validation failure remains a failure; one shared repair and the original 120-second generation deadline still apply.

Freeform input is not a guarantee of arbitrary physics or arbitrary new mechanics. The current runtime provides authored trajectories, staged interactions and visual/environmental changes. It does not provide a general fluid/vehicle/cloth simulation, full-body tracking, hand controllers, or model-generated executable code. New kinds of experiences can compose the existing tools; a genuinely missing capability requires a general runtime extension. The authoring instructions prohibit replacing the requested activity with an unrelated stationary conversation.

## Evidence

The deterministic checks cover stage gating, negative/unrelated commands, local dynamic phrases, continuous interpolation, relative heading, repeated travel, motion completion, pause/resume time and explicit character targeting. An actual provider-authored scene has also been rendered through the real native loader, with captured travel/underwater/return positions. This was explicitly labeled offline review of generated data. Physical-phone movement, comfort and broader visual-quality verification remain separate checks.
