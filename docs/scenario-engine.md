# AI-authored scenario execution

Braive takes a freeform situation and current ability. Spark authors an ordered experience: objective and automatically progressing stages. Wonder realizes that same plan as geometry, actors, paths and environmental changes. The phone executes those declarative instructions. It does not select a scene based on a topic keyword.

Skydiving, swimming and racing are examples in authoring guidance and tests. There are no production topic branches, embedded example scenes, or silent prerecorded/preset substitutes. The deterministic fixture under `tests/fixtures` exercises the generic runtime and is not an app resource. A generated scene can be bundled only through the explicit, ignored `Review` directory and `--include-review` diagnostic build option; normal generation excludes it.

## Shared capabilities

| AI-authored data | Native behavior |
| --- | --- |
| Guided scenario steps | Automatic timed or movement-completion progression, completed terminal goal |
| Natural speaking windows | Ordinary speech reaches the approved character; no ASK/name prefix |
| World or relative motion paths | Continuous participant/actor translation from the current position; relative paths use captured heading |
| Moving actor plus walk/run/swim behavior | Translation and app-owned joint motion on the registered neutral rig |
| Viewer-carried assembly roots | Equipment travels with translation while head rotation remains independent |
| Material/environment operations | Visibility, recoloring, opacity, thin surfaces, fog and lighting changes |
| Quiet action experiences | No dialogue request or movement commands needed |

The same monotonic active clock drives countdown, viewer/actor motion and character animation. STOP and interruptions freeze it; resumption continues from the preserved position/time. An in-flight absolute route is not restarted by repeating its command. Relative actions can make additional progress when repeated.

New plans and scenes declare `progression: guided`. Every action list is empty. Each nonterminal stage advances automatically; motion-completion stages start their own path on entry. A final terminal step means the activity has finished, not the start of an ongoing conversation. The summed stage timeline fits the countdown. A conversation window has an approved `conversation_target` and a timed completion, with transitions held while the participant is speaking or a relevant reply is pending. Action experiences disable dialogue entirely.

The active headset HUD stays quiet: status, timer and a small STOP hint. Stage prompts can be empty and should only mark meaningful transitions. STOP confirmation discards pending microphone ranges and arms after its spoken question/echo tail; exact fresh YES/NO answers decide end/resume. Legacy stored command scenes remain readable, but are excluded from new authoring.

## Coherence and limits

Coordinator cast, scene-node IDs, colors, approved props, stage IDs and stage action IDs must match. Licensed GLBs remain intact. The coordinator selects one of the approved soft Kenney adults; source palettes remain unchanged. A supported sit pose persists through dialogue. Missing props can use AI-authored procedural assemblies bound to an approved prop name. This does not permit invented asset IDs or replacement character meshes.

The backend validates graph references, stage order, path timing, meaningful actions, actual requested movement and resource bounds. Native preflight builds the real geometry offscreen and checks task visibility and visible surface depth in both eyes. Its depth pass measures each surface fragment rather than treating a large plane as entirely located at its center. A validation failure remains a failure; one shared repair and the ten-minute generation/readiness deadline still apply.

Freeform input is not a guarantee of arbitrary physics or arbitrary new mechanics. The current runtime provides authored trajectories, staged interactions and visual/environmental changes. It does not provide a general fluid/vehicle/cloth simulation, full-body tracking, hand controllers, or model-generated executable code. New kinds of experiences can compose the existing tools; a genuinely missing capability requires a general runtime extension. The authoring instructions prohibit replacing the requested activity with an unrelated stationary conversation.

## Evidence

The deterministic checks cover stage gating, negative/unrelated commands, local dynamic phrases, continuous interpolation, relative heading, repeated travel, motion completion, pause/resume time and explicit character targeting. An actual provider-authored scene has also been rendered through the real native loader, with captured travel/underwater/return positions. This was explicitly labeled offline review of generated data. Physical-phone movement, comfort and broader visual-quality verification remain separate checks.

The first command-driven physical test was rejected for micromanagement, character appearance and unexpected resume. The new guided contract/runtime and soft models pass offline checks; their combined physical-phone check is pending. See `docs/active-work.md` for current ownership and branch coordination.
